## 每次发布

1. 先确认用户授权、分支/远程、已有未提交内容和本次范围。修复/兼容调整递增patch，新增兼容功能递增minor，不兼容变更递增major；用户指定版本优先。两工具同批发布默认统一版本，项目差异分别说明。
2. 更新package.json、CHANGELOG、双语README及对应版本开发管理文件。开发中内容明确未发布，不混入正式说明。保留Agent等无关本地工作，不把整个脏工作区直接打包或提交。
3. 从清洁候选源码验证Node测试、双架构构建/签名/自检、轮询/锁/更新/提醒和界面；Claude另验证429。图形测试可能主动激活窗口，在隔离GitHub macOS运行；持续输入焦点测试仅在明确授权时手动运行，不加入普通CI。核实包无Agent、凭据、记忆、截图或缓存。核对Info.plist版本等于package.json，修改原生源码后先重建再在本地show。
4. 提交并推送main，CI通过后创建匹配的v版本标签，由GitHub Actions发布npm；Environment为npm，链接指向实际包。正式版latest，预发布next，不以本机npm publish代替。每次核对共用NPM_TOKEN的有效期和包权限；不得读取/记录值，不修改账号双重验证。
5. 发布Actions成功后继续核实Deployment success、公开registry版本/latest/gitHead、真实下载安装、升级自动重开/同版不重装、设置及登录配置保留。注册表尚未同步时记为待验证，不重复发布、不移动标签。已发布包不可覆盖；代码修正使用新版本，必要时先回退安装上一正式版。
6. 完成GitHub Release、管理清单、版本开发管理和MEMORY，关闭工作登记；文档跟进提交不移动已发布标签。
